# F7 device selection

Both runners now choose CUDA, then Apple MPS, then CPU automatically. They print the selected device before training.

## Run an experiment

From the repository root, install `requirements.txt` in your environment and ensure the dataset paths in your experiment JSON exist. For the default experiment, extract `ml-100k.zip` first.

```sh
.venv/bin/python -m cfrbm.user_based ubased.json
.venv/bin/python -m cfrbm.user_based ubased.json --device cpu
.venv/bin/python -m cfrbm.item_based ubased.json --device mps
```

Use `--device cuda` or `--device cuda:1` on a suitable CUDA host. Explicit unavailable devices produce an error; omit the option or use `--device auto` for automatic selection. Python callers can pass `device="cpu"` to `CFRBM`; pass input tensors on `model.device`.

## Validation and follow-up

CPU and MPS model training and both CLIs passed on Python 3.12.2 / PyTorch 2.14.1. The suite passed 28 tests, with one CUDA test skipped because CUDA hardware is absent. Test CUDA and indexed multi-GPU execution on a CUDA host.

This host hides MPS inside the execution sandbox. Run tests in a normal terminal with GPU access to exercise MPS. Device availability uses the [PyTorch MPS availability API](https://docs.pytorch.org/docs/stable/notes/mps.html). Random sequences need not match across device types.
