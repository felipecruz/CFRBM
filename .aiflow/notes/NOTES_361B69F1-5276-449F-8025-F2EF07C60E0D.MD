# F5 parity harness handoff

F5 adds eight deterministic parity checks in `tests/test_rbm.py`. Fixed inputs,
parameter state and Bernoulli samples avoid matching random-number streams.

## Run after F6

After implementing the PyTorch backend and installing its dependencies, run:

```sh
.venv/bin/python -m unittest tests.test_rbm -v
PATH="$PWD/.venv/bin:$PATH" make test
```

Require all eight parity checks to pass without skips. Today the test class
explicitly skips the legacy Theano source; this is not evidence of backend
parity. The nine existing tests pass. Temporary NumPy validation exercised the
eight reusable checks and confirmed five injected faults are rejected; the
PyTorch adapter itself still needs a real PyTorch run.

## Adapter contract

The adapter assumes the existing constructor, six parameter/gradient-memory
attributes, and `cdk_fun(vis, masks, **options)` returning a reusable callable.
If F6 changes the factory signature, update `TorchAdapter.train` only.
Sampling is intercepted at `torch.bernoulli`, preserving execution of the
model's sampling and normalization methods. Unexpected sample counts or shapes
fail the checks.

Keep the legacy momentum, negative-phase hidden factor and independent visible
Bernoulli behavior until F10–F12 intentionally update the oracle and tests.
CD-k chains and device-to-device parity are outside this CD-1 harness.
